## Purpose

`local_control` is the **external automation protocol** ("warpctrl") — the UI-agnostic, shared wire
layer that lets an out-of-process client drive a running Warp instance: list/create/activate
windows, tabs, panes, and sessions, and insert/replace input text. It is deliberately split from any
UI so the `app` and the `warp_cli` CLI share identical envelopes, an action catalog, discovery
records, selectors, and credential rules. **This is the existing out-of-process control seam** most
relevant to Marley's agentic-driving goal — but note it is *higher-level than raw bytes* (no
byte-write, no output read-back).

## Key types, modules & public API

`lib.rs` re-exports across seven modules:

- **`protocol`** (`src/protocol.rs`) — wire envelopes:
  - **`RequestEnvelope`** (`new(action)`), **`Action`** (`new(kind)`, `with_params(kind, T)`,
    `params_as::<T>()`), **`ResponseEnvelope`** (`ok(request_id, data)` / `error(request_id, err)`),
    `ErrorResponseEnvelope`, `ControlResponse`, `ControlResult`.
  - **`ControlError`** + **`ErrorCode`** enum incl. `LocalControlDisabled`, `UnauthorizedLocalClient`,
    `InsufficientPermissions`, `NotAllowlisted`, `InvalidParams`.
  - **`PROTOCOL_VERSION = 1`**. Param structs: `TabCreateParams { tab_type, shell }`,
    `TabActivateParams`, `TabCloseParams`, `TextParams { text }`, `ResizeParams`, `RenameParams`,
    `DirectionParams`, `FileOpenParams`, plus `TabType`/`Direction`/`TabActivationMode` enums.
- **`catalog`** (`src/catalog.rs`) — the **`ActionKind`** enum generated by the `define_action_catalog!`
  macro, with `ActionMetadata`/`ActionImplementationStatus`/`TargetScope`. Catalogued actions include
  `window.{list,inspect,create,focus,close}`, `tab.{list,create,activate,move,close,rename,color.*}`,
  `pane.{list,split,focus,navigate,resize,maximize,close,rename}`,
  **`session.{list,inspect,activate,previous,next,reopen_closed}`**, and
  **`input.{insert,replace}`** (`Text` params). *(Notably: no raw-byte write, no output-read action.)*
- **`selectors`** (`src/selectors.rs`) — **`TargetSelector`** → `WindowSelector`/`TabSelector`/
  `PaneSelector`/`SessionSelector`.
- **`auth`** (`src/auth.rs`) — **`AuthToken`** (`generate()`, `from_secret()`,
  `verify_authorization_header()`), **`CredentialRequest`**, **`ScopedCredential`**,
  **`CredentialGrant`** (`new(instance_id, action, ttl)`, `is_expired()`, `verify_for_action()`).
- **`discovery`** (`src/discovery.rs`) — `InstanceRecord`, `RegisteredInstance`, `InstanceId`,
  `ControlEndpoint`, `CredentialBrokerReference`, `discovery_dir()` (instance records under a
  discovery dir).
- **`client`** (`src/client.rs`) — `send_request(...)`, `request_credential(...)`,
  `probe_instance(instance)` (the CLI/client side that talks to a running instance, reqwest on non-wasm).
- **`selection`** — selection helpers.

## Marley relevance

**Classify: EXTEND (+ de-auth STUB).** This is the **ready-made out-of-process seam for goal (2)**:
an Ignibyte agentic panel/CLI can already `tab.create`, `session.activate`, and `input.insert` text
into a running Marley. The gaps to close:
- **Read-back is missing.** The catalog has no byte/output read action. To "read output back" you
  must **add a new `ActionKind`** (e.g. `session.read`) backed by `TerminalModel`/`BlockList`, or tap
  the byte stream in `app/.../event_loop.rs`. This is the main *extension* Marley needs here.
- **De-auth (goal 3):** gating lives in `auth.rs` + the `ErrorCode` variants
  `UnauthorizedLocalClient` / `NotAllowlisted` / `InsufficientPermissions` / `LocalControlDisabled`.
  For a frictionless local boot, **stub the auth path** (e.g. `AuthToken::verify_*` returns `Ok`, or
  bypass allowlisting) so an Ignibyte client isn't blocked — but keep the token plumbing for later.
- **Rebrand (goal 4):** "warpctrl", the discovery dir name, and `WarpServerConfig`-adjacent strings.
- **Rename:** only 2 dependents → `local_control` could become `marley_control` at moderate cost;
  the action-name strings (`"tab.create"`, etc.) are a wire contract — keep them stable unless you
  also update the CLI.

## Notes / gotchas

- **No raw byte I/O by design** — it drives the GUI/session at the *intent* level, not the PTY fd.
  Don't mistake `input.insert` for a PTY write; it injects into the active input editor.
- `edition = 2024`. `reqwest` only on non-wasm; `command` dep only on Windows + dev-deps.
- `ActionKind` is **macro-generated** (`define_action_catalog!`) — add actions in the macro
  invocation block (catalog.rs:167), not by hand-editing the enum.
- Auth is token + scoped-credential + TTL grant; credentials are brokered via discovery records.
