**gpui facts that shaped the design (read this turn):**
- `svg().text_color(c)` → svg paints iff its OWN `style.text.color` is Some (svg.rs:110
  `self.path.zip(style.text.color)`); an svg does NOT auto-inherit the ambient text color (the
  codebase always sets it explicitly). → the block-status svg sets `.text_color(gcolor)` explicitly.
- A div wraps its children's paint in `with_text_style` (div.rs:1823) — irrelevant here since we set
  the color explicitly, but it's WHY the deferred affordance set needs care (its hover color change
  wouldn't reach an svg child without per-svg handling).
- The proven pattern: top-tabs (app.rs:6056-6083) render `svg().size(px(ICON_SIZE))` inside
  `flex().flex_row().gap_2()` — the SAME row structure as the block header. So an svg in the block
  header flex row is byte-identical to shipping code. The one delta vs. top-tabs: the block row also
  holds the command TEXT, so it needs `.items_center()` to center the icon box against the text
  baseline (D5).

**The 3 clean-room SVG silhouettes (finalized paths — single filled `<path>`, no evenodd holes,
matching the #137 set; all 24×24; my own coordinates, §20):**
- `dot.svg` (StatusRunning ○): `<path d="M12 8.5a3.5 3.5 0 1 0 0 7 3.5 3.5 0 1 0 0-7z"/>` — a
  filled r=3.5 dot centered (12,12); a modest neutral "no result yet" marker (border-tinted). Filled
  (not a hollow ring) to avoid an evenodd hole → 100% render-certain (matches the robot-eye technique).
- `check.svg` (StatusOk ✓): `<path d="M4 12.2L9.3 17.5L19.8 6L18 4.2L9.3 13.9L5.8 10.4Z"/>` — a
  thick tick (~2.5 wide), short arm (4,12.2)→(9.3,17.5), long arm →(19.8,6); mitered inner vertex.
- `cross.svg` (StatusFailed ✗): `<path d="M6.85 5.15L18.85 17.15L17.15 18.85L5.15 6.85ZM18.85 6.85L6.85 18.85L5.15 17.15L17.15 5.15Z"/>`
  — an X as TWO diagonal bars (two subpaths, SAME winding [shoelace both +81.6] → nonzero fill unions
  them, no center hole; validated equivalent to agents.svg's two-eyes technique).
