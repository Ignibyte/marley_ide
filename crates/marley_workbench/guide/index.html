Marley Guide

Marley is Ignibyte's fork of the Zed editor, built around terminals and agents. It keeps everything Zed does and adds a rail of projects, a block terminal, agents recognized in any terminal, a browser inside the window, and tools that let your agents read your terminals and drive that browser. Each feature below starts with what it is, then how to use it, and names the ticket that shipped it.

Getting started

Installing, starting, updating, and where Marley keeps its things.

What Marley adds to Zed

What it is. Marley is Zed with a second layout and a set of Marley-only features. The editor, language support, git, settings, themes, extensions and the Agent Panel all work as they do in Zed.

AreaWhat you get
The Marley layoutA rail on the left listing each project with its terminals, Browser tabs, agent threads, worktrees and listening ports. Terminals open in the main area, and the Agent Panel docks on the right.
The block terminalEvery command is a block with its exit status. Blocks can be selected, copied, rerun, filtered, bookmarked, searched and saved as workflows.
Agents in terminalsClaude Code, Codex, Gemini CLI and OpenCode are recognized in any terminal, with an agent bar, notifications, rich input, and agents started in their own git worktrees.
Marley's tools for agentsAn MCP server that lets agents read your terminals, run commands at your prompt, and see and drive the Browser tab.
The Browser tabPages from Marley's own Chromium in a tab, with an element picker, annotations, a flight recorder and Playwright scripts.
System OneOff by default: local rules, and optionally a model, that label what agents are doing and hold risky browser clicks for you.

Install and update #502 · #517

What it is. just install builds Marley in the release profile from its checkout and installs the launcher, the binary, a menu entry and an icon under ~/.local.

How to use it

  1. In the checkout (/srv/stacks/marley_ide on the dev box), run just install. It waits while any other cargo command runs on the machine, since every project shares one target folder.
  2. The first build takes about ten minutes; an unchanged tree takes seconds. It ends by printing ~/.local/bin/marley at <commit> and the menu entry's path.
  3. If a Marley is running, it keeps its old build until you quit it and start it again.
  4. To update later: git pull, then just install, then restart Marley.
OptionWhat it does
just install --prefix DIRInstalls under DIR instead of ~/.local.
just install --regressRuns the golden set of end-to-end scenarios against the build first (about an hour), and installs only if every one passes.

The installed files are bin/marley (the launcher), lib/marley/marley (the binary, about 2 GB with its debug information), share/applications/marley.desktop and the icon. Marley's windows have the class dev.zed.Zed-Dev, which is what a Hyprland window rule matches.

Start Marley, and one Marley at a time #513 · #545

What it is. Start Marley from the app menu or with marley. Only one Marley runs on a data folder: a second launch hands its files and folders to the running one and brings its window forward.

How to use it

  1. Start it from the app menu (Super+Space, then type Marley), or run marley in a terminal.
  2. With Marley running, marley ~/some/file.md opens the file in the running window. The command prints that Marley is already running and was handed the path.
  3. Launching again from the menu brings the running window to the front.
  4. To run a second, separate Marley (for example to try something on a clean profile), give it its own data folder: marley --user-data-dir ~/marley-scratch. It behaves as a fresh install, with its own settings, logs and Chromium.

If Marley hangs, a new launch hands off to the hung one and exits. Find it with pgrep -x marley, kill it, and start again.

This guide #599

What it is. The page you are reading ships inside Marley. The ? button in the title bar, beside Sign In, opens it.

How to use it

  1. Click the ? in the title bar, or run marley: open guide from the command palette.
  2. With a project on screen, the guide opens in a Browser tab of that project, beside your work. A second click brings the same tab forward.
  3. With no project open, it opens in your system browser.
  4. Type in the filter at the top of the contents to find a feature.

Marley writes the page to ~/.local/share/marley/guide/index.html when you open it, so an updated Marley always shows its own guide.

Settings and the Marley page #515 · #514

What it is. Marley keeps its settings in ~/.config/marley/settings.json, in Zed's format, apart from a stock Zed's. The Settings window has a Marley page, first in its list, with every Marley setting.

How to use it

  1. Run marley: open settings to open the Settings window on the Marley page. Ctrl+, opens the Settings window at its last page.
  2. The page has six sections: Layout, Agents, Terminal, Push, System One and Privacy.
  3. Ctrl+Alt+, opens settings.json itself; Marley's keys sit in its "marley" block. The full list is in Settings reference.
  4. Telemetry is off by default: both toggles in Privacy start off.

To start from your Zed settings, copy ~/.config/zed/settings.json into ~/.config/marley/. Extensions download again on first use.

Terminals in the main area #441 · #449 · #455

What it is. In the Marley layout every terminal opens as a tab in the main area, beside your files. Nothing opens the bottom Terminal Panel.

How to use it

  1. Ctrl+` switches from an editor to the terminal you used last (or a new one), and from a terminal back to the editor you used last. Ctrl+J does the same while the bottom dock is closed.
  2. Ctrl+~ opens a new terminal in the main area.
  3. Right-click a folder in the project panel and choose Open in Terminal for a terminal in that folder.
  4. Tasks (Alt+Shift+T) run in main-area terminals too, and a rerun reuses the task's terminal.
  5. A folder you open for the first time starts with one terminal at its root, focused.

Vim's :! and external agents' login terminals still open the Terminal Panel, since they call it directly.

Quit and come back #494 · #575 · #576 · #577 · #485 · #486 · #606

What it is. Quitting keeps your projects, terminals and Browser tabs. They come back at the next launch.

How to use it

  1. Quit with zed: quit from the command palette. Ctrl+Q in a focused terminal goes to the shell, not to Zed.
  2. At the next launch, each terminal comes back as a shell in the folder it was in, without its scrollback, and keeps its terminal id.
  3. The first terminals of a launch open at the size they had last time, so a wide two-line prompt draws right from the start.
  4. Browser tabs come back on their pages, with your scroll and what you typed, while their Chromium still runs; after a logout they reload their saved address.
  5. Zed reopens only the project the window showed. The window's other projects stay in the rail, dimmed, with no rows (#606). Click one, or press Enter on it, to open it with its terminals and tabs; its right-click menu still moves or removes it.

Projects and their rows #438 · #468 · #442

What it is. The rail lists each project in the window under a header, and under the header its terminals, Browser tabs, Zed agent threads, git worktrees and listening ports, one row each. One row is highlighted at a time: the thing the window shows.

How to use it

  1. Click Add Project (the folder with a plus, top of the rail), then a recent project, Open Local Folders or Open Remote Folder.
  2. Click a row to show it: a terminal row focuses that terminal, a thread row opens the thread in the Agent Panel, a Browser tab row shows the tab.
  3. Fold a project with its chevron. A folded project's header counts its agents by state, as in 1 waiting, 2 working.
  4. Ctrl+Alt+J closes and opens the rail. It stays closed after a restart, and keeps its width.
  5. To close a thread you are done with, point at its row and click Archive at its end, or right-click it and choose Archive Thread (#605). Its row goes, and Zed's archive view in the Agent Panel brings it back.

Groups with no folder, and the rail's right-click menu #600 · #601

What it is. A right-click on the rail's empty space opens a menu for things that belong to no project. New Group… makes a named group with no folder: its terminals and agent CLIs start in your home folder, and its Browser tabs use a Chromium of the group's own. New Terminal, New Browser Tab and the agent CLIs in that menu open in a group named Home, which Marley makes the first time.

How to use it

  1. Right-click the empty space under the last row, or beside PROJECTS at the top of the rail.
  2. Choose New Group…, type a name and press Enter (Escape cancels; an empty name makes "Group"). The group lists after your projects, with a group icon, its chevron and its +.
  3. Use the group's + for New Terminal, New Browser Tab or an agent CLI. Threads, worktree agents and launch configs need a folder, so a group does not offer them.
  4. Or choose New Terminal, New Browser Tab or an agent from the empty space's menu: it opens in the Home group.
  5. Right-click a group's header for Rename Group… and Remove Group. Remove closes the group's terminals and tabs (Marley asks first if an agent there is working) and stops its browser.

A group keeps its place when you open a project while it is on screen, and comes back after a restart with its name, its order, its terminals in their folders and its Browser tabs (#601).

Drag to reorder the rail #602 · #613

What it is. Drag a project's or a group's header up or down to move it, with its rows, among the others; groups can sit between projects. Drag a terminal, Browser tab or thread row up or down to move it among the rows of its kind in its own group. The order is saved with the window and comes back after a restart.

How to use it

  1. Press on a header or a row and move the pointer. A card with its name follows the pointer.
  2. Over a place it can go, a line shows where it will land: above the target when you drag up, below it when you drag down. A header lands in the place of the block (a header and its rows) you drop it on; a row lands in the place of the row you drop it on.
  3. Let go. The rail keeps that order until you change it again.
  • A terminal row dropped on another open project's or group's header moves the terminal there, its shell still running and its scrollback kept (#613); its right-click menu's Move to Project does the same. Any other row only reorders: dropped on another group, on a header or outside the rail, it goes back where it was. Terminals under a worktree move among that worktree's terminals.
  • A press that barely moves is still a click, and opens the row.
  • While you drag, nothing else in the rail moves.
  • Under the attention order a row moves within its class (waiting, working, idle…), since what needs you still comes first; the order you set decides among rows of the same class.
  • Something new, like a terminal or a project you add later, goes after the ones you have placed.
  • A row's place is kept by the terminal, the page or the thread, not by its tab: moving a row does not move its tab in the panes.

Terminal rows: rename, close, last command #452 · #551

What it is. A terminal's row carries its name, where it is, and what it last ran, and renames or closes the terminal.

How to use it

  1. Double-click a row, or right-click it and choose Rename, to rename the terminal. The name shows on the tab too and survives restarts.
  2. Right-click and choose Close, or point at the row and click its close button. Marley asks first if a task or a working agent runs in it.
  3. Read the row's last line: the last command and its state, such as npm test · running, · done · 7 s, · exit 1 · 3 s in red, or · waiting for a password.
  4. The rail's filter finds a terminal by that last command too.

Dots that ask for you #438 · #538 · #551

What it is. A dot on a row means something happened there that you have not seen: a bell, a desktop notification, a finished agent turn, or a long command that ended.

How to use it

  1. A dot appears on the row; with the project folded, on the project's header.
  2. Click the row (or look at that terminal) to clear it.
  3. To try it: in a terminal run sleep 3; printf '\a' and click another terminal before three seconds pass.

Needs you: every agent waiting on you #508

What it is. While any agent waits on you, a Needs you section with a count sits at the top of the rail, above the projects: one entry per wait, the one that has waited longest first.

How to use it

  1. Read an entry: the agent, its project, what it asks, and how long it has waited (now, 3 m, 1 h 5 m).
  2. For a Zed agent thread's tool call, click Allow or Deny right in the entry. A prompt with more choices opens the thread instead.
  3. For Claude Code in a terminal, click the entry to go to its terminal and answer there.
  4. For an agent's browser click that Marley holds (see Consequential clicks), click Refuse or Allow.
  5. The entry leaves once the wait ends, wherever you answered it. The filter and folded projects never hide the section.

What needs you comes first #542

What it is. The rail sorts projects, and the rows under each, by attention: waiting on you or failed and unseen first, then finished and unseen, then working, then quiet agents (no update in N m), then idle. Ties keep the order you set by dragging (#602), else the window's.

How to use it

  1. Nothing to do: the order follows your agents.
  2. While the pointer is over the rail the order holds still, so a row never moves under your cursor.
  3. To keep the window's own order instead, set Rail Order to Window on the Marley page (Layout), or "marley": { "rail_order": "window" }.

A project's header: icon, changes, pull request #564 · #531

What it is. A project's header shows the project's own icon, the lines changed on its branch, and its pull request on GitHub.

How to use it

  1. The icon is the favicon or logo the repository holds (favicon.png, public/favicon.svg, src-tauri/icons/icon.png and similar names, or the icon index.html declares). Nothing is fetched.
  2. The counts, as in +12 ‒3, are the lines added and removed since the branch left its base, your uncommitted edits to tracked files included. Point at them to see the base. They follow each save within a second or two.

A project's right-click menu #453 · #507 · #581

What it is. Right-click a project's header for Move Project Up, Move Project Down, Clear Browser Data… and Remove Project.

How to use it

  • Move Project Up / Down moves the project one place in the rail, past a group as well as a project; it is the same order dragging sets (#602), and it is saved.
  • Clear Browser Data… asks, then closes the project's Browser tabs, stops its Chromium and deletes its profile, so every site in the project is signed out. Other projects keep their logins.

Port rows: the servers your project runs #521 · #603 · #604 · #614 · #615

What it is. The rail lists the TCP ports your processes listen on from inside the project's folders: a dev server, a database, anything. A row comes within seconds of a server's start and goes when it stops.

How to use it

  1. Start a server in the project, for example npm run dev or python3 -m http.server 8000.
  2. Point at its row to see the command line, folder and pid, and three buttons: Open (the URL in a Browser tab), Copy (the URL) and Stop.
  3. One click on the row only marks it. Double-click it, or press Enter once it is marked, to open its URL in a Browser tab, as Open does.
  4. Stop sends the process SIGTERM, after checking it still listens on that port.
  5. A server that a systemd service runs shows its unit on a line under the URL, and the pointer on the row says whether it is a user or a system service. Stop then stops the service, not the process, since the service would start a stopped process again: systemctl --user stop for a user service, systemctl stop for a system one, which asks for your password in the desktop's dialog. Point at Stop to see which it will do.
  6. If the service cannot be stopped (you cancel the password dialog, or are not allowed), a message says why and offers the command to run yourself, such as sudo systemctl stop app.service, with a Copy Command button.
  7. Right-click a port row for Open in a Browser Tab, Copy URL and, for a service, Restart Service, Stop Service and Show Logs. Restart keeps the row while the service comes back. The unit's line shows its state when it is not simply running (starting, failed in red, stopped). Show Logs follows the unit's journal in a new terminal of the project.
  8. A port a Docker or Podman container publishes is listed too: named by its container under the project its Compose folder is in when docker ps answers, else under CONTAINERS after the projects with the container's address. Stop runs docker stop; if the engine refuses, a message offers the command to run yourself. Docker's own service is never stopped from a row.

A server bound to 0.0.0.0 gets a URL on 127.0.0.1. A server started in one of Marley's terminals runs in no service of its own, so Stop signals it.

Send the editor's selection to an agent #549

What keeps agents in check #516 · #562 · #574

What it is. The limits on what the tools hand an agent and what they let it do.

  • The server listens on 127.0.0.1 only and refuses a request from any other origin.
  • Secrets in terminal output, commands and the browser console reach agents as [redacted: kind]: private keys, tokens and passwords assigned to names, Authorization headers, cookies, cloud and API keys, JWTs, and your own marley.redaction_patterns.
  • URLs lose the values of parameters named like tokens, keys, secrets, passwords, codes and sessions; the page snapshot holds no field values; typed text is counted, never kept.
  • Your agent client asks you before each write (Claude Code does by default), and every browser action happens in front of you with the Agent chip naming it.
  • A browser call with no tab acts in the agent's own project, never another project's page.
  • No tool runs script an agent supplies, and agents navigate to http and https only.

Programs outside Marley drive its browser #524 · #584

What it is. Let a program you name (Playwright MCP, a script) read or act in Marley's Browser tabs, with a token of its own that you can cut off.

How to use it

  1. Run marley: browser clients, type the program's name, choose read or act, and press Enter.
  2. The program points Marley's bridge at the endpoint file Marley shows. It sees only the browser tools its grant allows.
  3. A tab it acts in shows Driven by <name> with Cut Off, which refuses its token at once.
  4. For a program on another machine, copy the SSH line Browser Clients shows; it holds no token and keeps working after Marley restarts.

The Browser tab

A web page from Marley's own Chromium, in a tab beside your code, that you and your agents use together.

Open a Browser tab #488 · #500 · #504 · #539

What it is. A tab that shows a page of Chromium running in the background for the project. Its row in the rail shows the page's icon, title and host.

How to use it

  1. Click a project's +, then New Browser Tab, type an address and press Enter.
  2. Or run marley: open browser (shows the Browser tab you used last, or opens one), or press Ctrl+T in a Browser tab for a new one.
  3. The first time, the tab reads "Starting Chromium…" for a moment.
  4. Local pages also open here from the terminal: see Links in terminals.

Chromium is /usr/lib/chromium/chromium, or chromium on your PATH, or the binary MARLEY_CHROMIUM names. Websites see it as Chrome.

A Chromium per project #507 · #583 · #581

What it is. Each project gets its own Chromium and profile, so a login in one project is not a login in another, and each project's cookies and storage survive restarts.

How to use it

  • A project's Chromium starts with its first Browser tab and keeps running after Marley quits (so restored tabs find their pages) until you log out or remove the project.
  • To sign a project out of every site, right-click its header and choose Clear Browser Data…, or run marley: clear project browser data.
  • To see or stop the Chromium units: systemctl --user list-units 'marley-browser-*', then systemctl --user stop <unit>.

Chromium listens on no network port: it talks only to Marley's relay, through files only you can read.

The toolbar and the address bar #490

What it is. Back, Forward, Reload, the address bar, and the three tools for agents: the element picker, annotations and Record this.

How to use it

  1. Ctrl+L selects the address bar. Type a URL, a host such as localhost:3000 (http for local hosts, https otherwise), or words to search DuckDuckGo. Enter goes; Escape restores the page's address.
  2. Alt+Left and Alt+Right go back and forward; Ctrl+R or F5 reloads.
  3. A page that fails to load shows Chromium's error page, and the address bar keeps what you typed.

Use the page as in a browser #489 · #493 · #495 · #582

What it is. Clicks, typing, scrolling, the clipboard, new tabs, drop-down lists and dialogs all work as in Chrome.

How to use it

  • Ctrl+C and Ctrl+V use the system clipboard. Ctrl+S and Ctrl+W stay Zed's (save, close the tab).
  • A link that opens a new window opens a new Browser tab beside its opener, with the focus.
  • A <select> opens as Marley's list, with its groups and disabled options; Alt+Down, F4 or Space opens a focused one.
  • A page's alert, confirm or prompt shows as a card naming the site; Enter answers OK, Escape Cancel.
  • A title the page sets later (an unread count, say) follows on the tab and its rail row.

Headless Chromium draws no browser UI of its own: file choosers, downloads and context menus do not show yet.

Let an agent drive #492 · #574

What it is. Agents with Marley's tools see the page you see and act on it with the same clicks and keys, in front of you.

How to use it

  1. Ask the agent, for example: "Open localhost:3000, click Sign in, and tell me what the console says."
  2. The agent's client asks you before each action (Claude Code does by default).
  3. The page acts without taking your focus. The toolbar's Agent chip names each action while it runs; typed text shows as its length.
  4. A page an agent opens goes in its own project's Browser tab, behind your current tab.

Pick an element for the agent #496 · #518 · #497

What it is. Point at the exact element you mean, add a sentence, and send it to the agent, which then reads everything about that element.

How to use it

  1. Click in the agent's terminal first, so it is the terminal you used last.
  2. In the Browser tab, press Ctrl+Shift+C or click the crosshair. Chromium's highlight follows the pointer; click the element. The click does not reach the page.
  3. The pick waits in a tray under the toolbar. Type what the agent should know in its caption, such as "Make this green", and press Enter.
  4. Marley types a line such as [browser pick 1: button “Save” on localhost:3000; browser_pick id 1] Make this green into the terminal and takes you there. Press Enter to send it.
  5. The agent reads the pick with browser_pick: its locators, HTML, styles, nearby texts, and on a React dev build its component and source file.

Where the page has source maps, the pick shows its click listener's source file and line (click src/app.ts:2); a click on it opens that line in the editor.

Check the fix #505

What it is. After the page changed, find the picked element again and see what changed about it.

How to use it

  1. After the agent's change, reload the page and click Check on the pick in the tray.
  2. Marley finds the element again by its most durable locator and opens a card: the crop at the pick beside the crop now, and what changed (box, styles, text, role and name).
  3. The pick keeps the verdict, such as 2 changes, no change or not found. Agents get the same with browser_check_pick.

Annotate the page #498

What it is. Draw boxes with notes over the page, for yourself or the agent; agents can draw their own.

How to use it

  1. Click the pencil, or run marley: annotate. Drag a box around something, type a note, and press Enter (Escape drops it).
  2. Your boxes use the theme's warning color; an agent's use its accent color, with a sparkle.
  3. Click a note and press Delete to remove it. Loading another page clears them.

Record this, and a test from it #499 · #506

What it is. Marley keeps the last minute of the page you are looking at. One click saves it, so you can tell the agent "it broke just now" and it can see what you did, and even draft a Playwright test from it.

How to use it

  1. When something goes wrong, click the red dot in the toolbar, or run marley: record this. A toast names the recording.
  2. Tell the agent: "Read the latest recording and tell me what I did." It sees your clicks, keys, how many characters you typed (never the text), console messages and requests.
  3. Ask: "Draft a Playwright test from that recording." browser_draft_test answers a test with the best locator for each step and a path under your tests folder; the agent writes the file.

Recordings live in ~/.local/share/marley/browser/recordings/, never in a project.

Playwright scripts #523

What it is. Keep Playwright scripts in Marley, for one project or for every project, and run them on a Browser tab's page.

How to use it

  1. Click the Playwright Scripts button in the toolbar, or run marley: playwright scripts.
  2. Type a name and press Enter for a new script from Marley's template; it opens in the editor.
  3. Click Run: the script runs on the tab's page in a terminal beside it, and the tab stays in front. The first run installs Marley's own Playwright.
  4. When a script fails, Marley saves the tab's last minute as a recording and names it in a toast.

Scripts live in Marley's config folder, never in a repository.

System One

Readings about what your agents and pages are doing: from Marley's own local rules, and optionally from a model. Off until you turn it on. Nothing here approves, sends or stops anything.

Turn it on #565

What it is. A layer that asks typed questions (a yes or no, a choice, a score) about states Marley builds. The rules provider answers from Marley's own rules on this machine, with no key and no request; the typesafe provider asks TypeSafe's Jev model about what the rules leave open.

How to use it

  1. Add to your settings (or use the Marley page's System One section): 
    "marley": {
  "system_one": {
    "enabled": true,
    "provider": "rules",
    "projects": ["~/code"],
    "uses": { "stop_kind": "act", "stall_kind": "act", "inbox": "act" }
  }
}
  2. Each use has a mode: off, shadow (asked and logged, shown only in Decisions), suggest (shown with a question mark) or act.
  3. For a model: set "provider": "typesafe" and give Marley the key, in MARLEY_SYSTEM_ONE_KEY or through Decisions' Set Key (the system keyring).
  4. Only projects under a folder in projects send anything; those in metadata_only_projects send facts and none of their text. Every value is masked with the secret rules first.
  5. marley: system one check asks one question about the last command of the terminal you used last, to see a request and an answer.

Decisions #565

What it is. A tab listing the day's System One calls: when, which use, which project, the provider, the reading, the time taken and the cost.

How to use it

  1. Run marley: open decisions.
  2. Click a row to see the state exactly as it was sent and the answer as it came.
  3. The header shows the day's spend against the budget (daily_budget_cents, 50 by default), where the key comes from, and Run Check, Set Key and Forget Key.

What a stopped agent needs #566

What it is. An idle Claude Code's row says why it stopped: done · checked (done, and a command ran after the last edit), done · claimed, asks you, blocked, still going or interrupted.

How to use it

  1. Set uses.stop_kind (Stop Kind on the Marley page).
  2. Read the idle row. When your prompt had several parts, a last line names one the agent's message leaves out: not covered: "Add a license."
  3. Your next prompt clears it.

Local rules settle an interrupt, an unanswered permission, or a last sentence that asks you something, with no request.

A stuck agent #569

What it is. A working Claude Code's row gets a warning mark when it may be stuck: looping? (the same tool line three times in a row) or stalled? (quiet with no busy tool).

How to use it

  1. Set uses.stall_kind (Stall Kind). The loop rule is local; quiet checks come after stall_check_after_seconds (60) and at two, four and eight times it.
  2. Point at the mark to see why. In act mode a stuck agent in a terminal you are not looking at also posts one notification.

Marley never stops or types into an agent on a flag.

Find by words, for agents #567

What it is. Two agent tools, browser_find and terminal_find, that answer "the sign in button" or "where the server refused the connection" with an element ref or a line, instead of the agent reading everything.

How to use it

  1. Set uses.browser_find and uses.terminal_find. The tools are listed only while their use is on.
  2. In a running Claude Code, reconnect Marley's server with /mcp so it lists them.
  3. The query's own words answer first, locally; the model ranks what they leave open.

Consequential clicks wait for you #571

What it is. An agent's click in a Browser tab that would pay, delete, send in your name or change an account waits on a card for you to Allow or Refuse.

How to use it

  1. Set uses.click_consequence. By default only agents with no permission prompts of their own wait; "browser_click_pause_agents": "all_agents" makes every agent wait.
  2. A card under the toolbar reads, for example, "Claude Code wants to click button “Place order”, which pays, on shop.example", with Refuse and Allow; a toast points to it, and the Needs you section lists it.
  3. Allow clicks the same element on the same page; Refuse, or 25 seconds without an answer, tells the agent you did not allow it.

The card never takes the focus by itself; click it (or the toast's Show), then Enter allows and Escape refuses.

Risk and route in Needs you #568 · #570

What it is. Each Needs you entry carries chips saying what the waiting action would do (destroys, credentials, rewrites history, sends out, installs, outside project), and a mark for who should answer it (for you, for the manager, could proceed, unclear). The riskiest come first.

How to use it

  1. Set uses.inbox (Inbox Risk) and uses.question_route (Question Route).
  2. Read the chips before answering; point at a mark to see whether a rule or the model set it.

Nothing here answers for you: Allow and Deny stay your clicks.

A running command that printed an error #572

What it is. A command that prints a failure and keeps running (a dev server whose build broke) marks its terminal's row with a red × and the line, and posts one notification; a second says when it recovered.

How to use it

  1. Set uses.running_error (Running Error).
  2. Start a dev server; when its output shows a compiler, test runner or runtime failure and it is still running five seconds later, the row and a notification say so.
  3. When it prints that it built or served again, the mark clears and a notification says it recovered.

The fleet

Agents a workflow store reports, where they run and what they work on. Marley defines what a store sends and draws it; until the Rustal services serve it, a pseudo provider shows example data.

The Fleet panel #607

What it is. A panel in the right dock that lists every agent your providers report, grouped under its host, with its work item, its phase and its state.

How to use it

  1. Add a provider to your settings. The pseudo one shows Marley's example data: 
    "marley": {
  "fleet": { "providers": [ { "kind": "pseudo" } ] }
}
  2. Run marley: toggle fleet, or click the server icon in the status bar.
  3. Read each row: the runtime's mark and the agent's name; its work item's key and phase as name n/m; a yellow mark when it waits on a question, a red one when its run failed; and a chip with its state, stale when it has not reported for three polls.
  4. With no provider set, the panel says the fleet is not set up and names the setting.

The panel reads its providers only while it shows.

An agent's snapshot #608

What it is. The selected agent's state, work, run, host and tokens, under the Fleet panel's list.

How to use it

  1. Click an agent's row. The panel splits: the list above, the snapshot below.
  2. Read its state and for how long, its runtime, model, host and folder; its work item; its run as a strip of phases (green passed, blue active, red failed); its host's CPU and memory; its tokens today; and its question with the options.
  3. Press Up or Down to move to the next agent while the panel has the focus.
  4. Drag the line between the list and the snapshot to resize them.

A part the store does not offer is left out.

The Agent tab #609

What it is. One agent in full, in a tab in the center: its phases in time, its events, its host's resources over time, its tokens and its neighbours.

How to use it

  1. Double-click an agent in the Fleet panel, press Enter on the selected one, or click Open in its snapshot. Opening it again brings the same tab forward.
  2. Read the timeline: each phase a bar from its start to its end, its gates under it, a failed gate's message in red.
  3. Read the events, newest first, and the CPU, memory and network lines over the last 30 minutes Marley watched.
  4. Click an agent under On This Host to open its tab.

The graphs start empty after a restart, and the tab is not reopened after one.

Hosts over SSH #610

What it is. Marley reads each host you list itself: a small script it sends over SSH (or runs on this machine) reports CPU, memory, disk, network and the agent processes running there. Nothing is installed.

How to use it

  1. List the hosts: 
    "marley": {
  "fleet": {
    "hosts": [
      { "ssh": "me@build-1", "name": "build-1", "id": "host-build-1" },
      { "local": true }
    ]
  }
}
  2. Open the Fleet panel. Each host's header shows a line of its resources; its claude and codex processes show as agents.
  3. A process whose MARLEY_FLEET_SESSION is a store's agent id joins that agent, whose snapshot then shows the host's numbers and the process. The others are listed under Hosts as running.
  4. A host that does not answer reads unreachable: point at the chip for SSH's error. Its store agents read offline.

SSH runs with BatchMode: a host needs a key or an agent. A destination starting with - is refused.

Real workflow stores #611

What it is. A store that answers Marley's fleet contract, over MCP or plain HTTP, listed in the Fleet panel beside or instead of the pseudo one.

How to use it

  1. Add it under marley.fleet.providers: { "kind": "mcp", "command": "…", "args": ["…"] }, { "kind": "mcp", "url": "…" } or { "kind": "http", "url": "…" }, with an optional name, and bearer_env naming the environment variable that holds its token.
  2. Read its header: ready, connecting, unreachable with the cause (point at it for the whole message; its agents read offline), stale after three polls with no answer, or incompatible with the contract it speaks.

Marley retries an unreachable store after 1, 2, 4, 8, 16, then every 30 seconds. The token is sent as a bearer and never logged. One store's trouble leaves the others as they are.
